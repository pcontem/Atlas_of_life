# Image triage tool

A single web page for choosing the images of genus entries by clicking buttons. The choices go to GitHub as a
small file; a workflow then adds the images to the entries, stores them in the media store and opens a pull
request for review.

## Use

1. Open `tools/triage/index.html` in a browser (download the file, or open it from a clone of the repository).
2. Check *Repository* (`pcontem/Atlas_of_life`), *Branch* (`main`) and *Volume* (`pseudosuchia`), then **Load**.
3. Pick a genus on the left (filter: undecided candidates, genera with an entry, all, changed in this session).
4. For each candidate click **photo**, **life**, **fossil**, **skeletal** or **✕ reject** (click again to undo).
   Keyboard: `←` `→` move, `1`–`4` kind, `X` reject, `0` clear, `[` `]` previous/next genus, `Enter` enlarge,
   `Esc` close. Edit the caption in the box if needed (English, short: what and where).
5. Images already in an entry are shown at the top with **accepted / outdated / unreviewed** (CLAUDE.md §4.4 I4:
   a `life` restoration is accepted only when it matches current knowledge; `restoration_checks` of the volume).
6. **Send to GitHub** — needs a token (see below). Choices are kept in the browser until they are sent;
   **Download JSON** saves them as a file instead.

Rules the tool enforces: licences outside CC0 / public domain / CC BY / CC BY-SA cannot be chosen; `photo` only for
living genera. The workflow also keeps the 8-per-kind limit. Not checked by the tool (judge them yourself):
museum models, statues, stamps, maps, size charts, pre-1950 restorations, AI images, pictures of other taxa
(Commons categories and article pictures often include relatives).

## Token

GitHub → Settings → Developer settings → Fine-grained personal access tokens → *Generate new token*:
repository access *Only select repositories* → this repository; permissions → *Contents: Read and write*.
The token is kept only in this browser (localStorage) and sent only to api.github.com.

## What happens after Send

- The page creates a branch `triage/<volume>-<time>` from *Branch* and adds
  `data/triage/<volume>_decisions/<time>.json` (one file per send, so sends never conflict).
- `.github/workflows/triage-apply.yml` runs on that branch: `scripts/apply_triage.py` (adds the images to the
  entries with `review: unreviewed`, review changes), `scripts/media.py fetch/push` (downloads them into the media
  store), `scripts/triage_data.py` (refreshes the candidate list), build, validate, commit, and a pull request to
  `main` whose description lists what was added or skipped and the validation result.
- Merge the pull request after looking at it. Genera without an entry keep their choices in the decisions files;
  they are applied by the first triage run after their entry exists.

## Files

- `data/triage/<volume>.json` — candidates per genus (Commons files and open-access article figures from
  `data/raw/<volume>/`), generated by `python3 scripts/triage_data.py <volume>`.
- `data/triage/<volume>_decisions/*.json` — the sent choices (record of who chose what, kept in git).
- Local test without GitHub: `python3 -m http.server` in the repository root, then open
  `http://localhost:8000/tools/triage/index.html?local`.
